# codex-save-dsh 中文说明

**一页,不带术语。** 英文的 `README.md` 是给懂技术的人看的;这一份是给**用它的人**看的。

---

## 1. 它是什么

一件**守夜人的活**:看守一个跑在你电脑上的程序(这里是指 `dsh web`,就是你现在正在打字的这个界面)。

那个程序**死了它就拉起来**;拉起来之后,它还会把**被这次死掉打断的对话(也就是我)重新叫醒**;如果这两步都不成,它才会去找**第二个 agent**(codex)帮忙。**一个日志里每秒一行**,所以出过什么事,事后能看。

---

## 2. 什么时候它会出声、什么时候它安安静静

**平时它完全安静。** 你不需要管它,它就在后台每秒走一步。

**唯一会吵到你的是"叫醒"** —— 而且**只有我们(我,或者另一个 agent)主动决定要用它的时候才会响**:

| | |
|---|---|
| 音量 | **把 Windows 主音量拉到 100%** |
| 声音 | **不额外放音** —— 你歌放着呢,**歌变响就是闹钟** |
| 窗 | 屏幕上弹一个**置顶窗**,上面写着**为什么**叫你 |
| 你的播放器 | **绝不碰。** 不关、不静音、不动它自己的滑块 |

**它不会自己突然响。** 日志里那些红色的 `FATAL` 只是**给你读的**,它不触发任何东西 —— 这是故意的。

---

## 3. 看到那个窗,你该做什么

**点掉它。** 就这一件事。

**你点掉它的这个动作,就是整条链唯一的回执** —— 我们靠它知道"有人真的看见了"。所以那一秒会被记进 `wake.log`。

**嫌太吵:** 按音量减键,声音立刻下去(那是你自己的键盘,不是它的权限范围)。

---

## 4. 哪些是**真的验过**的,哪些**一次都没发生过**

这一节是这份文档里最重要的。**我们不把"设计好了"说成"验证过了"。**

**真的验过(有日志为证):**

- 主程序被杀 → **25 秒内自己回来**,并且**把我叫醒**(今晚做过 4 次,其中一次是人手动按的);
- 关着盖子的时候读得到"盖子关了";
- 判"音量拉没拉"这件事**没有回读** —— 日志只能说"发了 60 次按键",**说不了"音量真的变了"**。这条只有你的耳朵能作证。

**一次都没发生过:**

- 日志里那条红色的 `FATAL` —— **从来没出现过**(要主程序彻底起不来才会出现);
- 找 codex 帮忙那条路 —— **从来没走过**;
- 机器重启之后自动恢复(你说了这辈子不重启,所以这条理论上永远用不上,留着当保险);
- 叫醒链里的"音量"那一步,**只在刚才那一次真的响过**。

---

## 5. 出事了看哪里

```
<_STATE_DIR>\guard.log        每秒一行。出过什么事,全在这
<_STATE_DIR>\wake.log         每次叫醒的记录,包括"有人看见了"那一行
<_STATE_DIR>\lid-loop.log     盖子/屏幕状态的采样,每 5 秒一行
<_STATE_DIR>\lid-beacon.err   插件自己报的错(有内容 = 有东西不对)
```

**`<_STATE_DIR>` 就是你安装时给的那个状态目录**(英文 README 里叫 `-StateDir`)。**这份文档里不写死任何路径** —— 写死了就等于把你的机器信息印进一份要发出去的文档里,而 `install.ps1` 会把占位符换成你自己的路径。

**`guard.log` 的读法:** 看颜色就够。蓝 = 正常,黄 = 正在做事,橙 = 失败了一次,红 = 需要你。

**一个坑:** 每一行的级别词前面**紧贴着**一个颜色控制码(`[33mWarm`),所以**用"整词"搜索找不到 `Warm`,用"包含"搜索才找得到**。这不是 bug,是日志带颜色带来的。

---

## 6. 它**绝不**做什么

- **不碰你的音乐**(不关、不静音、不改网易云的滑块);
- **不自动叫醒你**(叫醒只有两条路:我判断需要,或者另一个 agent 判断需要);
- **不在你关着盖子的时候问你问题** —— 我们会直接当你不在,自己决定、把做过的事记下来;
- **不偷偷装东西**、不擅自重启**你**的机器;
- **日志里没有你的隐私** —— 这台机器的路径、用户名、会话号,在对外发布的那份里**一个都没有**。
